# wxshadow W^X 影子内存机制 — 完整技术分析

## 一、基础概念：PTE 与页表

### 1.1 ARM64 四级页表

ARM64 使用 **4级页表** 将 48 位虚拟地址翻译为物理地址：

```
虚拟地址 (48位)
┌─────────┬─────────┬─────────┬─────────┬────────────┐
│ PGD(9位)│ PUD(9位)│ PMD(9位)│ PTE(9位)│ 页内偏移(12位)│
└────┬────┴────┬────┴────┬────┴────┬────┴─────┬──────┘
     ↓         ↓         ↓         ↓          ↓
  一级表   二级表    三级表    四级表     4KB页内位置
```

### 1.2 PTE (Page Table Entry)

PTE 是最后一级页表条目，64位，结构如下：

```
┌──────────────────────────────────────────────────────────┐
│ 高位属性(UXN等) │ 物理页帧号(PFN) │ 低位属性(权限/状态)  │
│   [63:52]       │   [47:12]       │   [11:0]            │
└──────────────────────────────────────────────────────────┘
```

关键属性位：
- **bit[7] (AP[2])**: 只读标志。置1 = 只读，置0 = 可写
- **bit[6] (AP[1])**: 用户态可访问
- **bit[54] (UXN)**: User eXecute Never。置1 = 不可执行

**核心要点：修改 PTE 中的 PFN，就能让同一个虚拟地址指向不同的物理页。** 这就是 wxshadow 切换页面的原理。

### 1.3 页粒度权限

ARM64 的读/写/执行权限是 **页粒度** 的（4KB），不能对单个字节设不同权限。

当影子页被设为 `--x`（只执行）时，**读这个页上的任何地址**都会触发 read_fault，不只是断点地址。这恰恰是 wxshadow 想要的效果——任何对受保护页面的读取（包括 CRC 校验）都会被拦截并重定向到原始页。

## 二、TLB 与页表缓存

### 2.1 TLB 是什么

TLB (Translation Lookaside Buffer) 是 CPU 内部的 **页表缓存**：

```
CPU 访问虚拟地址 0x7200001234:

  不用TLB:  虚拟地址 → 查4级页表(4次内存访问) → 物理地址    慢
  用TLB:    虚拟地址 → TLB命中 → 物理地址                  快 (1个周期)
```

### 2.2 为什么必须刷新 TLB

wxshadow 修改 PTE 后，CPU 还在用 TLB 里 **旧的** 缓存结果。不刷 TLB，CPU 根本不会去重新查页表，修改等于没做。

```c
*pte = new_pte_value;                    // 修改页表 — 内存中生效了
wxshadow_flush_tlb_page(vma, addr);      // 告诉CPU: TLB缓存作废，重新查页表
```

wxshadow 准备了 3 种刷新方法作为 fallback：
1. `flush_tlb_page` — 精确刷单页
2. `__flush_tlb_range` — 刷地址范围
3. 手动 `TLBI` 指令 — 通过 ASID 直接发 TLB 失效指令

## 三、W^X 读写执行分离原理

### 3.1 传统内存 vs W^X

- **传统内存**：一个页面同时可读+可写+可执行 → 安全检测工具可以读取代码（算CRC32）也能执行代码
- **W^X 影子内存**：同一虚拟地址在不同时刻指向不同物理页，**读和执行看到不同内容**

### 3.2 双页面布局

```
                    虚拟地址 0x7200001000
                           │
              ┌────────────┼────────────┐
              ▼                         ▼
     ┌─────────────────┐     ┌─────────────────┐
     │   原始物理页      │     │   影子物理页      │
     │                  │     │                  │
     │  真实的函数代码   │     │  大部分是原始代码  │
     │  (没有BRK)       │     │  但断点处是 BRK #7 │
     │                  │     │                  │
     │  权限: r-- (只读) │     │  权限: --x (只执行)│
     └─────────────────┘     └─────────────────┘
      CRC校验读这个 ✓            CPU执行这个 ✓
      读到的是原始代码            执行的是带BRK的代码
```

### 3.3 三种页面状态

```
状态            PTE 指向    权限         用途
─────────────────────────────────────────────────
STATE_SHADOW_X  影子页      --x (只执行)  正常执行，含BRK断点
STATE_ORIG_R    原始页      r-- (只读)    供CRC校验读取干净数据
STATE_STEPPING  原始页      r-x (读+执行) 单步执行原始指令(临时)
```

### 3.4 状态机

```
         read_fault          exec_fault
  SHADOW_X ──────────→ ORIG_R ──────────→ SHADOW_X
     │                                       ↑
     │ brk_handler                           │ step_handler
     ↓                                       │
  STEPPING ──────────────────────────────────┘
```

## 四、影子页分配详细流程

当用户态调用 `prctl(0x57585801, pid, addr)` 设置断点时：

### 步骤1：地址对齐与 VMA 查找

```
用户态传入: addr = 0x7200001234 (要下断点的地址)

page_addr = addr & ~0xFFF = 0x7200001000  (页对齐)
offset    = addr & 0xFFF  = 0x234         (页内偏移)

kfn_find_vma(mm, addr) → 找到对应的VMA
VMA: vm_start=0x7200000000, vm_end=0x7200100000
nr_pages = (vm_end - vm_start) / 4096 = 256 页
```

### 步骤2：分配数据结构

```
wx_region (56字节)           page_info 数组 (256个)
┌──────────────────┐        ┌────────────────────┐
│ mm = 进程mm_struct│        │ [0] page_info (空)  │
│ vm_start         │───────→│ [1] page_info (空)  │
│ vm_end           │        │ ...                 │
│ pages ───────────│────┐   │ [idx] page_info ←───│─── 目标页
│ nr_pages = 256   │    │   │ ...                 │
│ refcount = 1     │    │   │ [255] page_info (空)│
└──────────────────┘    │   └────────────────────┘
                        └──→ kzalloc分配, 全部清零
```

### 步骤3：分配影子物理页

```
1. 读取当前PTE，提取原始物理页帧号
   pte = get_user_pte(mm, 0x7200001000)
   pte_val = *pte  →  例如 0x0000008043210FC3
   orig_pfn = (pte_val >> 12) & MASK = 0x80432

2. 分配1个新物理页作为影子页
   shadow_va = __get_free_pages(GFP_KERNEL, 0)  → 内核虚拟地址
   shadow_pa = va_to_pa(shadow_va)               → 物理地址
   shadow_pfn = shadow_pa >> 12                   → 物理页帧号

3. 复制原始内容到影子页
   orig_va = pa_to_va(orig_pfn << 12)  → 原始页的内核虚拟地址
   memcpy(shadow_va, orig_va, 4096)    → 完整复制4KB
```

### 步骤4：写入 BRK 并切换 PTE

```
4. 在影子页的目标偏移处写入断点指令
   *(uint32_t*)(shadow_va + 0x234) = 0xD42000E0  // BRK #7

5. 修改PTE: 指向影子页, 设置为只执行(--x)
   原PTE:  [orig_pfn | 权限位]     → 原始权限
   新PTE:  [shadow_pfn | 0x0C0]   → 只执行

6. 刷新TLB, 使新PTE生效
   flush_tlb_page(vma, 0x7200001000)

7. 刷新指令缓存
   flush_icache(0x7200001000)
```

### 分配后的内存布局

```
进程虚拟地址空间                     物理内存

0x7200001000 ──PTE──→  影子物理页 (shadow_pfn)
(权限: --x)             ┌──────────────────────┐
                        │ ...原始代码拷贝...     │
                        │ 偏移0x234: BRK #7    │ ← 断点
                        │ ...原始代码拷贝...     │
                        └──────────────────────┘

                        原始物理页 (orig_pfn)
                        ┌──────────────────────┐
                        │ ...原始代码...         │
                        │ 偏移0x234: 真实指令    │ ← 单步时执行这个
                        │ ...原始代码...         │
                        └──────────────────────┘
                        (暂时没有PTE指向它, 但pfn被记录在page_info中)
```

## 五、断点命中完整生命周期

```
时间线    页面状态              发生的事情
─────────────────────────────────────────────────────────────

  t0     SHADOW_X (--x)       CPU执行影子页, 一切正常
         PTE → 影子页

  t1     SHADOW_X (--x)       PC到达断点地址, 执行BRK #7
         PTE → 影子页          → ARM64异常 → brk_handler

  t2     [在brk_handler中]     1. 通过PC查找region和page_info
                               2. 打印寄存器快照 (x0-x7, lr, sp)
                               3. 应用寄存器修改 (如果配置了)
                               4. 切换PTE → 原始页 (r-x)
                               5. pi->state = STEPPING
                               6. 开启单步模式 (MDSCR_EL1.SS=1)

  t3     STEPPING (r-x)       异常返回, CPU在同一PC重新取指
         PTE → 原始页          这次取到的是原始指令（不是BRK）
                               CPU执行这条原始指令

  t4     STEPPING (r-x)       单步异常触发 → step_handler
         PTE → 原始页          1. 切换PTE → 影子页 (--x)
                               2. 刷新icache
                               3. pi->state = SHADOW_X
                               4. 关闭单步模式

  t5     SHADOW_X (--x)       回到正常执行, 继续跑影子页代码
         PTE → 影子页          直到下次命中BRK
```

**关键点：BRK 命中后 PC 不变，切回原始页后 CPU 在同一地址重新执行，这次执行的是真实指令。原始指令被完整执行，不会被跳过。**

## 六、CRC32 校验欺骗流程

### 6.1 读故障触发

```
  t0     SHADOW_X (--x)       正常执行状态

  t1     SHADOW_X (--x)       CRC校验代码执行 ldr x0, [x1]
         PTE → 影子页          x1 指向受保护的代码地址
                               影子页权限是 --x (不可读!)
                               → 数据中止异常 (Data Abort, WnR=0)
                               → do_page_fault_before hook

  t2     [在read_fault中]      ESR分析: 读错误
                               切换PTE → 原始页 (r--)
                               pi->state = ORIG_R
                               skip_origin = 1 (跳过内核原始处理)

  t3     ORIG_R (r--)         异常返回, CPU重试 ldr 指令
         PTE → 原始页          这次读到的是原始代码 (干净的, 无BRK)
                               → CRC32 计算结果正确! ✓

  t4     ORIG_R (r--)         CRC校验完毕, 程序继续执行
         PTE → 原始页          下一条要执行的代码在这个页上
                               原始页权限是 r-- (不可执行!)
                               → 指令中止异常 (Instruction Abort)
                               → do_page_fault_before hook

  t5     [在exec_fault中]      ESR分析: 执行错误
                               切换PTE → 影子页 (--x)
                               pi->state = SHADOW_X

  t6     SHADOW_X (--x)       回到正常状态, 继续执行影子页
         PTE → 影子页
```

### 6.2 页粒度的影响

由于权限是页粒度的，CRC 校验读取受保护页上的 **任何地址** 都会触发 read_fault（不只是断点地址）：

```
影子页 4KB (--x):
  偏移 0x000: 原始指令 (拷贝)
  偏移 0x234: BRK #7    ← 断点
  偏移 0x500: 原始指令 (拷贝)

CRC校验读偏移0x000 → 触发read_fault → 切到原始页 → 读到原始指令
CRC校验读偏移0x234 → 触发read_fault → 切到原始页 → 读到原始指令(不是BRK)
CRC校验读偏移0x500 → 触发read_fault → 切到原始页 → 读到原始指令
```

执行方面不受影响：`--x` 允许执行整个页。非断点地址处是原始指令的拷贝，执行效果和原始页一模一样。

### 6.3 写故障处理 (COW/动态修改)

```
  t0     SHADOW_X (--x)       正常执行状态

  t1     SHADOW_X (--x)       某处代码写入此页
                               → 数据中止异常 (Data Abort, WnR=1)
                               → write_fault handler

  t2     [在write_fault中]     页面被修改 → 影子页内容可能过时
                               恢复PTE → 原始页 (原始权限)
                               释放影子页, 清除所有断点
                               state = NONE
                               (断点永久丢失, 无自动恢复)
```

## 七、同一页多断点

### 7.1 数据结构布局

每个 page_info 最多容纳 16 个断点 (MAX_BP_PER_PAGE=16)：

```
page_info (1464字节)
┌────────────────────────────────────────┐
│ orig_pfn    = 0x80432                  │  原始物理页帧号
│ shadow_pfn  = 0xA1234                  │  影子物理页帧号
│ shadow_page_va = 0xFFFF...            │  影子页内核虚拟地址
│ state       = STATE_SHADOW_X           │  当前状态
│ stepping_task = NULL                   │  正在单步的线程
│ bp_count    = 3                        │  3个断点
│                                        │
│ bps[0]:  addr=0x7200001234  active=1   │  断点1
│          mod_count=1                   │
│          mods[0]: x0 = 0x1234          │  命中时把x0改成0x1234
│                                        │
│ bps[1]:  addr=0x7200001340  active=1   │  断点2 (同一页不同偏移)
│          mod_count=0                   │  纯观测, 不改寄存器
│                                        │
│ bps[2]:  addr=0x72000017A8  active=1   │  断点3
│          mod_count=2                   │
│          mods[0]: x0 = 0              │
│          mods[1]: x1 = 0xDEAD         │
│                                        │
│ bps[3..15]: (空闲槽位)                  │  最多16个断点/页
└────────────────────────────────────────┘

影子物理页内容:
偏移0x000: 原始指令...
偏移0x234: BRK #7    ← bps[0]
偏移0x238: 原始指令...
偏移0x340: BRK #7    ← bps[1]
偏移0x344: 原始指令...
偏移0x7A8: BRK #7    ← bps[2]
偏移0x7AC: 原始指令...
```

### 7.2 添加断点到已有影子页

当同一页已有影子页时，`set_bp` 直接在影子页写入新 BRK，并追加 bp_entry 条目。

### 7.3 部分删除断点

删除单个断点时，只把该偏移处恢复为原始指令，影子页和其他 BRK 保持不变。全部断点删完后才释放影子页、恢复原始 PTE。

## 八、边界情况与已知问题

### 8.1 第17个断点幽灵植入 (严重性: 中)

`bp_count > 15` 时，bp_entry 不会创建，但 BRK 指令照样写入影子页。后果：
- BRK 触发但 `find_bp` 找不到条目 → 无法应用寄存器修改
- `del_bp` 也找不到 → 无法删除，只能靠整页清理

### 8.2 删除后重设同地址断点的 bug (严重性: 中)

`del_bp` 只清 `active=0`，不删条目。再次 `set_bp` 同地址时，匹配到旧条目后跳过创建，**不会重置 active=1**。BRK 写入了但条目仍 inactive → `set_reg` 失败。

### 8.3 STEPPING 窗口多线程断点丢失 (严重性: 高)

STEPPING 是整页粒度的。线程A单步时，整页切到原始代码，同页所有 BRK 对其他线程不可见：

```
线程A命中断点A → 整页切到原始代码 → STATE_STEPPING
线程B经过断点B → 看到原始指令 → 直接执行过去（断点丢失）
线程A单步完成 → 切回影子页 → BRK恢复
```

单线程不受影响。spin-wait 超时 (10001次) 后 → SIGTRAP 杀进程。

### 8.4 fork() 后子进程崩溃 (严重性: 高)

fork 复制页表，子进程继承影子页 PTE。子进程执行到 BRK → handler 查不到子进程的 mm → "not our breakpoint" → SIGTRAP → 子进程被杀。

wxshadow 没有 fork hook，无法在子进程中恢复原始映射。

### 8.5 COW 后断点静默丢失 (严重性: 中)

COW 导致内核分配新物理页，`orig_pfn` 失配 → `validate_page_mapping` 失败 → auto cleanup → 断点消失，用户态不收到通知，无重建机制。

### 8.6 exit_mmap 32 区域硬限制 (严重性: 低)

栈上数组只有 32 个槽位。超过 32 个被 hook 的 VMA 区域时，超出部分不会被清理 → PTE 悬空 → 内核 "Bad page map" 错误。

### 8.7 删除断点时未检查 STEPPING 状态 (严重性: 低)

`del_bp` 直接写影子页，不检查 STEPPING 状态。STEPPING 期间页面映射到原始页，写入影子页不会立即生效，但切回后该位置已是原始指令，时序上有微妙的竞争窗口。

## 九、wxshadow vs 硬件断点对比

```
              硬件断点 (HW BRP)             wxshadow
─────────────────────────────────────────────────────────────
数量          ARM64通常 4~6 个              每页16个，页数不限
检测难度      读DBGBCR_EL1即可发现          需对比影子页和原始页物理内容
CRC32校验     不改代码，天然通过             通过W^X页面切换欺骗
性能          零开销，硬件比较              每次命中: 异常+PTE切换+TLB刷新
多线程        per-CPU，天然隔离             STEPPING窗口会丢断点
反调试绕过    容易被检测                    专门设计来对抗检测
```

### 选择建议

- **目标没有反调试** → 硬件断点更好。简单、快、无副作用
- **目标有完整反调试体系** (调试寄存器检测、CRC校验、/proc检测等) → wxshadow 更适合
- **最佳实践** → 组合使用：关键被校验函数用 wxshadow，其他位置用硬件断点
